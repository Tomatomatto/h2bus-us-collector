# h2bus-us-collector

미국 조달 공고(수소버스 관련) 자동 수집기. GitHub Actions에서 주 1회 무인 실행되어
`data/notices.csv`를 갱신하고, 담당자는 엑셀(Power Query)로 이 CSV를 직접 연결해 본다.

기존 H2BusRadar(로컬 PC 실행, 유럽·미국 13개 소스, SQLite/대시보드)와는 목적·환경·수명주기가
달라 별도 저장소로 운영한다.

## 1. 엑셀 연결 주소

```
https://raw.githubusercontent.com/Tomatomatto/h2bus-us-collector/main/data/notices.csv
```

엑셀에서: 데이터 탭 → 데이터 가져오기 → 웹에서 → 위 주소 붙여넣기 → 연결.
매 실행마다 이 파일이 갱신되므로, 엑셀에서 "새로고침"만 누르면 최신 공고를 받아볼 수 있다.

## 2. 수집 대상 (1곳, 최종 확정)

| 기관 | 주소 | 상태 |
|---|---|---|
| MTA Flint | https://www.mtaflint.org/purchasing | 정상 수집 중 |

**OCTA는 자동 수집 대상에서 제외됐다.** 로컬 사내망에서는 타임아웃이었으나(§2 진단,
`OCTA_DIAGNOSIS.md`), 2026-08-07 GitHub Actions 실행으로 사내망 문제가 아니었음이
확인됐다. 다만 `cammnet.octa.net`의 예전 공고 목록 페이지에는 더 이상 공고 링크가
없고, 안내에 따라 이동한 신규 조달 시스템(`procurement.opengov.com/portal/octa`)은
Cloudflare 봇 차단으로 자동 접근 자체가 불가능하다(403). 패치오더 §2 판정표의
"403/봇 차단 → 수집 대상 제외" 케이스로, 수기 확인 대상으로 전환했다
(`collectors/octa.py`는 조사 기록으로 남겨두되 `collect.py`에서는 호출하지 않는다).

## 3. 실행 주기 · 수동 실행

- 자동: 매주 월요일 09:00 UTC (`.github/workflows/collect.yml`)
- 수동: 저장소의 Actions 탭 → "Collect procurement notices" → **Run workflow**
- 로컬 실행: `python collect.py` (저장소 루트에서)

## 4. `data/notices.csv` 열 정의 (15개 · 순서 고정)

**엑셀이 이 CSV를 직접 읽으므로 열 이름·순서를 임의로 바꾸지 않는다.**

| # | 열 이름 | 내용 | 없을 때 |
|---|---|---|---|
| 1 | 확인일 | 최초 수집 실행일 (YYYY-MM-DD) | 필수 |
| 2 | 기관 | `MTA Flint` | 필수 |
| 3 | 공고번호 | 원문의 공고 번호 | 없으면 제목 앞 40자 |
| 4 | 제목 | 공고 제목 원문 | 필수 |
| 5 | 품목구분 | 버스 / 부품 / 충전인프라 / 용역 / 기타 | 기타 |
| 6 | 연료 | 수소 / 배터리 / 기타 / 불명 | 불명 |
| 7 | 대수 | 숫자만 (원문에 명시된 경우만) | 빈칸 |
| 8 | 예산금액(USD) | 숫자만, 통화기호·쉼표 제거 (원문에 명시된 경우만) | 빈칸 |
| 9 | 게시일 | YYYY-MM-DD | 빈칸 |
| 10 | 마감일 | YYYY-MM-DD | 빈칸 |
| 11 | 상태 | 진행 / 마감 / 낙찰 / 취소 | 진행 |
| 12 | 낙찰자 | 낙찰 시에만 | 빈칸 |
| 13 | 수집방식 | 항상 `자동` | 필수 |
| 14 | 원본URL | 해당 공고를 확인할 수 있는 주소 | 필수 |
| 15 | 비고 | 판별 근거 등 | 빈칸 |

대수·예산금액은 **원문에 숫자가 명시된 경우에만** 채운다. 제목의 차량 길이("40-FOOT"),
충전소 용량("capacity"), 기관 보유 대수("fleet of")는 구매 대수가 아니므로 채우지 않는다
(`tests/test_parsing.py` 참조).

기존 행은 누적되며 삭제되지 않는다. 재실행 시 동일 (기관+공고번호) 건은 마감일·상태·낙찰자만
갱신하고, 확인일과 다른 정보는 최초 수집 시점 값을 유지한다. 마감일이 지난 "진행" 건은
자동으로 "마감"으로 바뀐다.

## 5. 자동 수집이 1곳뿐인 이유

미국 측 조사 대상 기관 중 MTA Flint만 로그인 없이, robots.txt를 우회하지 않고, 브라우저
자동화 없이 정적 HTML로 접근 가능한 상시 공고 목록을 제공한다. OCTA를 포함한 나머지
10곳은 조달 시스템이 자동 접근을 막거나(로그인 필요, 봇 차단) 상시 공고 목록 페이지
자체가 없어 담당자가 수기로 확인해야 한다.

## 6. 개인 계정 운영 유의

이 저장소는 개인 GitHub 계정으로 운영된다. 계정 소유자가 바뀌거나 계정이 비활성화되면
GitHub Actions 자동 실행이 조용히 멈춘다. 사내 조직 계정 승인이 나면 저장소를 조직으로
이전(transfer)하고, 위 "엑셀 연결 주소"를 새 경로로 갱신해야 한다.

## 7. 실행 이력 확인

`data/run_log.csv`에 매 실행 결과(실행시각/기관/상태/수집건수/오류메시지)가 누적 기록된다.
특정 기관이 2회 연속 0건을 반환하거나 접속에 실패하면 GitHub Actions 잡이 실패로 표시되고
저장소 소유자에게 알림이 간다 — 수집이 조용히 멈추는 것을 막기 위함이다.

## 8. 원문 보존

매 실행 시 가져온 원본 HTML을 `raw/{기관}/{날짜}.html`에 보존한다 (파싱 오류 검증용).

## 9. 신규 수소버스 공고 이메일 알림

자동수집 결과 중 **새로 발견된 건**(기존 `notices.csv`에 없던 건)이면서 **연료='수소' AND
품목구분='버스'** 인 경우에만 지정된 수신자에게 이메일을 보낸다 (`collectors/notify.py`).
이미 알고 있던 공고가 마감일만 갱신되는 경우 등은 알림 대상이 아니다.

GitHub Actions는 이메일 발송 기능이 내장되어 있지 않으므로, 표준 SMTP(`smtplib`, 사내
CV News Clipping 프로젝트의 이식 가능한 발송 방식과 동일 계열)로 직접 보낸다. Outlook COM
자동화 방식은 클라우드 러너에 Outlook이 없어 사용할 수 없다.

### 설정 방법 (최초 1회)

저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서 아래
6개를 등록한다. **절대 코드나 이 README에 실제 값을 적지 않는다.**

| 시크릿 이름 | 내용 | 예시 |
|---|---|---|
| `SMTP_HOST` | SMTP 서버 주소 | Gmail: `smtp.gmail.com` |
| `SMTP_PORT` | SMTP 포트 (SSL) | Gmail: `465` |
| `SMTP_USERNAME` | 로그인 계정 | `sender@gmail.com` |
| `SMTP_PASSWORD` | 비밀번호 (Gmail은 일반 비밀번호가 아닌 **앱 비밀번호** 필요) | - |
| `FROM_EMAIL` | 발신 표시 주소 (보통 `SMTP_USERNAME`과 동일) | `sender@gmail.com` |
| `TO_EMAIL` | 수신자 이메일 주소 | `recipient@example.com` |

Gmail을 쓸 경우: Google 계정 → 보안 → 2단계 인증 활성화 → **앱 비밀번호** 생성 → 그 16자리
값을 `SMTP_PASSWORD`에 등록한다 (일반 로그인 비밀번호는 동작하지 않는다).

시크릿을 등록하지 않은 상태에서도 신규 수소버스 공고가 없는 평소 실행은 그대로 정상
동작한다 — 알림 대상이 있을 때만 환경변수를 읽으므로, 미설정 상태로 방치해도 기존
수집 기능에는 영향이 없다. 다만 신규 수소버스 공고가 실제로 발견됐는데 시크릿 미설정
등으로 발송에 실패하면, 그 실패도 Actions 잡 실패로 표시된다(조용히 놓치지 않는다).
